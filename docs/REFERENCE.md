Importer references translated into `tools/smw_import.py`:

- LoROM address conversion and decompression from `assets/util.py`
- Level object length parsing, Map16, palette, graphics, level pointer, and sprite pointer addresses from `assets/compile_resources.py`
- Foreground/background GFX upload order from `kUploadGraphicsFiles_FGAndBGGFXList` in `src/smw_00.cpp`; level `105` uses tileset `7`, which uploads GFX `15`, `1B`, `17`, and `14` into level VRAM order.
- Sprite GFX upload order from `kUploadGraphicsFiles_SpriteGFXList` and `UploadGraphicsFiles` in `src/smw_00.cpp`; level `105` and its direct pipe target `1CB` use sprite GFX setting `8`, which uploads GFX `20`, `13`, `01`, and `00` into the `$6000-$7FFF` sprite VRAM window.
- Screen-exit property semantics from `src/smw_0d.cpp` and level-load destination construction from `src/smw_05.cpp`
- Lunar Magic Universal's current screen-jump object behavior: extended object `01` updates the object stream screen cursor after the marker object is parsed, which keeps later level geometry on the intended screens.
- Player graphics source data from `GFX32`/`GFX33`, player palettes, and `PlayerGFXRt` tile pointer/OAM placement tables.
- SPC upload bank addresses from `assets/compile_resources.py`: engine `0x0E8000`, samples `0x0F8000`, level music `0x0EAED6`, overworld music `0x0E98B1`, and credits music `0x03E400`.
- Vanilla secondary entrance tables from `0x05F800`, `0x05FA00`, `0x05FC00`, and `0x05FE00`, including the Yoshi Island 1 return-pipe entry at `0x1CB`.
- BRR preview decoding follows the native `assets/util.py` BRR decoder and the SPC upload block format used by `src/smw_spc_player.cpp`. The vanilla DSP sample directory starts at SPC RAM `$8000`.

Palette note: raw 8x8 GFX tiles are not enough to show final colors. The level layout preview renders through Map16 tile words because those words carry CGRAM row bits 10-12, priority, and flip flags. The importer now writes `palettes/level_*_palette.json` as a full 256-color level CGRAM image. For the verified vanilla ROM, this is assembled from the level header's back-area color, BG palette, FG palette, sprite palette, layer 3, object, berry, player, and animated-color tables. The importer also recognizes the Lunar Magic custom palette hijack at `$00A5C0 -> $0EF570` and the `$0EF600` per-level palette pointer table structurally, but the validation gate still uses the clean SMW USA ROM unless ROM support is explicitly widened later.

GFX note: foreground/background and sprite VRAM atlases are resolved per level. Clean vanilla levels use the native upload tables, while Lunar Magic Super GFX bypass data is recognized through the table pointer at `$0FF7FF` and slot words for `FG3/BG1/FG2/FG1` and `SP4/SP3/SP2/SP1`. Vanilla SMW GFX slots are stored as 3bpp for most normal files, so generated previews expand them into 4bpp and populate 128 tiles per uploaded GFX file, yielding the full 512-tile BG and sprite VRAM windows needed by Map16/tilemap words. The importer can also resolve ExGFX pointer tables structurally, but generated validation assets are still produced from the verified vanilla ROM.

Map16 note: foreground Map16 IDs are not a flat `map16_id * 4` index into `$0D8000`. The importer now ports the native `InitializeMap16Pointers()` table from `src/smw_05.cpp`, including the global-vs-tileset bitmask, tileset base pointers, and the grassland/YI1 override slots for tilesets `0` and `7`. Level `105` therefore resolves tile `0x100` through the YI1 grassland Map16 pointer path before rendering the Godot atlas and runtime tile sprites.

Audio note: the importer preserves the original SPC engine/sample/music banks. Godot runtime playback now uses a C# internal APU probe that parses the SPC upload streams, reads the vanilla instrument table from the engine RAM image, decodes selected BRR entries from the sample directory, and streams them through `AudioStreamGenerator`; the WAV files are only importer verification artifacts. The command probes cover the native SPC port-1 jump and two-note command shapes, and the menu exposes decoded BRR sample probe buttons for samples `09`, `0E`, and `10`. The menu music buttons drive a small C# pattern sequencer through imported BRR instruments for level/overworld/credits previews. Gameplay level entry now reads the imported level-header `music_index` and starts the corresponding internal preview automatically, including after pipe transitions. The current mixer prunes inactive voices, caps active voices and per-frame generator fill work, and can be disabled with `--smw-no-audio` or `SMW_AUDIO=0` for performance isolation. Exact SMW music and SFX still require porting the complete SPC command sequencing, ADSR, pitch sweep, echo, and DSP state.

Runtime collision note: `GameScene` now renders the generated Yoshi Island 1 Map16 placements through a single palette-aware custom draw layer and derives temporary merged AABB collision rectangles from the imported placement source labels. Imported diagonal ledge, diagonal pipe, and slope edge cells emit per-Map16-tile slope segments rather than long connected-component averages, so adjacent slope objects do not create large false walkable lines. Slope-family support/fill/assist cells are deliberately not emitted as temporary rectangular solids because those AABBs create hidden stair steps inside visual terrain slopes. Right diagonal pipe cells are the exception: floor-slope, interior-body, and underside Map16 IDs are tracked separately, so the outer traversal/ceiling slope lines remain available while interior body cells can still reject embedded player positions without reusing floor cells as horizontal body blockers. Standard slope collision now reads the Map16 ID family for the actual edge tile and emits gradual `4 px`, normal `8 px`, or steep `16 px` surface segments instead of treating every slope cell as a full 45-degree ramp. Right diagonal pipe underside tiles can emit temporary ceiling slope segments, shown in cyan debug overlays, so the pipe body can block upward movement while slope interiors remain passable. Player floor-slope contact currently probes center plus both feet and checks the leading foot first when moving, which makes diagonal pipe lips less fragile at tile boundaries while the native Map16 act-as slope code remains unported. The importer follows Lunar Magic Universal's current `0x12` standard slope projection, including native slope overwrite tile adjustment, and the newer left diagonal ledge lower-row placement, bottom-row plain fill, first-fill-row notch, and slope/line overwrite flags. This is useful for playable traversal, but it is not a substitute for the final Map16 act-as table, slope semantics, and block interaction routines.

Runtime diagonal-pipe underside note: the temporary right-diagonal pipe underside solver now skips active horizontal walking when Mario is not moving upward. This keeps a headless reproduction at `x=2056,y=304` in level `105` while walking left under the sloped pipe instead of letting underside correction shove Mario into a pipe transition path. Diagonal-pipe body and ceiling recovery also yields when Mario is already supported by the imported floor-slope cells, which prevents the previous one-frame shove from `x=2025` to `x=2048` inside the sloped pipe cluster. Stationary embedded-pipe recovery still resolves the older `x=880,y=304` probe to the known `x=896` boundary. The pipe body's coarse horizontal blocker can still push Mario out of the green pipe volume; replacing that with exact native Map16 act-as sampling is still pending.

Runtime block interaction note: `std_generic_08`/Map16 `0x11E` turn-block cells are now a focused runtime interaction for the Yoshi Island 1 slice. A non-small spin jump landing on these imported cells hides the tile in the batched Map16 layer, removes the tile from the runtime tile lookup, rebuilds collision data, and logs `smw-runtime: block_break`. Imported block-style sprite actors `0x83` and `0xB9` are also treated as temporary solid actor bodies; the flying question block `0x83` gets a deterministic wing bob and resolves top, side, and underside player contacts. Underside hits on `0x83` now mark the block used, swap to the used Map16 face, and resolve the Lunar Magic Universal content rule `X&3`; the level `105` flying block currently exercises the big-Mario flower branch. This is intentionally narrower than the native block system; exact turn-block bounce sprites, debris, timers, native item actor spawning, below-hit behavior, and the full Map16 act-as dispatch remain pending.

Runtime player graphics note: `GameScene` now draws Mario from the generated GFX32 player atlas through the native `PlayerGFXRt` data path for the first big-Mario pose set. The importer preserves `player_xy_disp_index_index` from `$00DCEC`, `player_xy_disp_index` from `$00DD32`, signed X/Y displacement words from `$00DD4E/$00DE32`, `powerup_tileset_index` from `$00DF16`, `tiles_index` from `$00DF4C`, OAM tile descriptors from `$00DFDA`, head/body tile pointer indices from `$00E00C/$00E0CC`, tile X-flip flags from `$00E18C`, `kSetPlayerPose_WalkingPoseCount` from `$00DC78`, and `kSetPlayerPose_AnimationSpeedTable` from `$00DC7C`. The runtime maps OAM descriptors `0/1/2/3` through the dynamic upload pointer math used by `PlayerGFXRt_00F636`, so head/body source tiles come from GFX32 offsets instead of treating descriptor bytes as raw source tile IDs. Other direct/static descriptor tile numbers are temporarily suppressed because they refer to native dynamic VRAM/OAM char numbers rather than raw GFX32 atlas indices; rendering them directly produces stray pixel fragments until the exact VRAM upload mapping is ported. Mario's visual node is snapped to the integer player position while the physics state keeps subpixels, matching SNES OAM placement more closely and avoiding subpixel texture shimmer. The generated PNG atlases use a full OBJ palette row 8 layout: fixed colors `0-1`, vanilla object colors `2-5`, and player dynamic colors `6-F` from `$00B2C8`; the importer writes Mario, Luigi, Fire Mario, and Fire Luigi variants, and the runtime currently selects variant `2` for the fire power-up. The current runtime player state tracks SMW power-up forms `0..3` and uses a temporary 16px small/ducking and 32px big-family collision height while preserving foot position across form changes and duck toggles. Mario's rendered OAM bridge applies the native -1px screen-space Y bias, and small/ducking OAM is shifted up by another 16px because those states still occupy the lower half of a 32px player anchor. The current animation bridge uses deterministic frame timers for idle/walk/run, switches high-speed running into the native `+4` pose range, maps opposite-input ground turns to pose `13`, switches grounded ducking to native pose `60`, and cycles spin-jump pose/facing through the native `DATA_00CE99/00CEA1` tables; static descriptor VRAM mapping, cape/Yoshi variants, cape OAM, priority, hide-mask behavior, and native hitbox tables still need the direct SMW pose/OAM port.

Asset-pipeline note: Python is currently used only for the offline development extractor because it is fast to iterate and easy to compare against ROM bytes. The Godot runtime consumes generated assets and does not call Python. The intended end state is a C# importer/editor tool or C# asset-pipeline project so asset extraction can live inside the Godot/.NET codebase.

Pipe target layout note: vanilla Yoshi Island 1 resolves the screen `07` pipe to level `1CB`, not `0CB`. Level `1CB` uses underground tileset `3`; the partial object expander now covers its standard horizontal pipes plus underground ceiling ledges and ceiling edges, so `level_1CB_partial_tilemap.json` contains the target room's main shell geometry. Pipe objects now use Lunar Magic Universal's foreground-preservation rule, so overlapping terrain stays in front of shaft/body cells in both generated previews and runtime tile selection.

Runtime level asset note: `GameScene` loads the current level through `generated/smw/manifest.json` and uses the manifest's per-level `tileset_assets` and `layout_preview` paths. Level `105` is still the startup level, but the renderer no longer assumes `level_105_tileset7_*` filenames internally.

Runtime transition scaffolding note: `GameScene` can rebuild world geometry, collision rectangles, HUD previews, and player spawn from another imported level. The CLI argument `--smw-test-level=1CB` is used by `tools/check-headless.sh` to verify that the imported direct pipe target loads with generated collision rectangles.

Runtime entrance note: `GameScene` resolves entry placement through the imported vanilla tables rather than scanning for the first plausible floor tile. Main entrances read `$05F000` for the Y index and `$05F200` for X/action, matching the `LoadLevel` table conversion in `smw_05.cpp`; secondary screen exits use the screen-exit destination as the secondary entrance ID and then read `$05F800/$05FA00/$05FC00/$05FE00` for target level, Y, X, and entrance action. The runtime now applies a bridge for those entrance actions: settings `1..4` briefly lock input and move Mario left, right, up, or down with the native pipe-action direction, while setting `6` starts the vanilla shoot-out vector from `PlayerState07_ShootOutOfPipe`. The verified YI1 path now loads `105 -> 1CB` at the `1CB` main entrance and `1CB -> 105` through secondary entrance `1CB`.

Runtime viewport note: the game scene now uses a `256x224` logical viewport, matching the SNES visible level area, while `Main` requests a `768x672` Wayland window for normal visible runs. The camera follows horizontally and vertically, clamped to generated tile bounds, so lower terrain in Yoshi Island 1 remains inspectable during drops. Debug asset previews no longer determine the playable viewport scale.

Runtime debug launch note: `--smw-test-spawn=x,y` places Mario at an explicit world coordinate after the level is loaded, and `--smw-test-powerup=small|big|cape|fire` forces the runtime form for hitbox checks. When both are present, the power-up is applied before the spawn coordinate so the requested debug coordinate is not shifted by the form-change foot-preservation logic. These are intended for reproducible viewport captures and lower-route inspection.

Runtime input script note: `--smw-input-script=/path/to/script` autostarts the game and feeds deterministic per-frame C# `FrameInput` values. The current bridge is intentionally simple: one segment per line, blank lines and `#` comments ignored, first token as frame count, and remaining tokens as held inputs (`left`, `right`, `down`, `jump`/`B`, `spin`/`A`, `run`/`X`/`Y`). Native `smw/` converter directives beginning with `@` are ignored for now, and menu/shoulder tokens `Start`, `Select`, `Up`, `L`, and `R` are accepted as no-ops so generated `.input` files can be reused for in-level probes. `jump` and `spin` set the pressed-edge flag only on the first frame of their segment. This is not a TASVideos/BK2 parser yet, but it gives headless checks and future TAS conversion work a runtime input injection point.

Runtime RCON controller note: live debug control supports one-shot `input <frames> ...`, single-frame `tap ...`, persistent `hold ...`, and `release`/`neutral`. Persistent holds generate `JumpPressed`/`SpinPressed` only on the first frame where the held button changes from up to down, so `hold right run jump` behaves like a controller button press and then a held jump rather than repeatedly retriggering jump every physics tick.

Runtime debug overlay note: `--smw-debug-overlays` adds world-space diagnostics for the current partial port: player hitbox/feet/form label, active `256x224` camera rectangle, merged collision rectangles, slope lines, pipe trigger rectangles, goal tape trigger rectangles, runtime sprite actor hitboxes, imported sprite/object markers, screen boundaries, and coin/block markers inferred from generated Map16 tile sources. The debug HUD also reports the Map16 coordinate, tile ID, collision role, and source label under Mario's feet. These gizmos are debugging aids for comparing importer placement and collision behavior; they are not game objects and should stay disabled for normal playtests.

Runtime collision probe note: RCON `collision [x y radius]` reports the nearest temporary solid rectangles and slope segments around a world point, including solid step-up/vertical flags and slope ceiling flags. With no explicit point it probes around Mario's current hitbox center. This is intended for stuck-player and misplaced-pipe reports where the overlay is visible but the exact blocker is not obvious from a screenshot.

Runtime diagonal pipe probe note: RCON `pipe [x y radius]` reports nearby generated right-diagonal pipe floor/body/ceiling cell coordinates. It uses the same tracked cell sets that feed temporary pipe collision recovery, so a stuck report can distinguish missing floor-slope support from a body or ceiling cell being interpreted too broadly.

Runtime pipe note: pipe debug rectangles are rebuilt from imported screen-exit records and the corresponding generated vertical pipe top, horizontal pipe end, or right-diagonal pipe cluster Map16 placements. For level `105`, this puts active triggers on the screen `07` pipe geometry, including the sloped pipe cluster, instead of the old hardcoded screen `01` marker; for level `1CB`, the horizontal pipe end now has a left/right-triggered rectangle for the return screen exit.

Runtime sprite note: `GameScene` loads generated `sprite_layer.sprites` records and renders their spawn points as debug markers with sprite IDs. The current coordinate decode uses the vanilla screen nibble plus 8-bit x byte and low y nibble, which is enough to inspect Yoshi Island 1's 34 imported sprite records. The first runtime actor layer turns common YI1 enemy records into simple moving/stompable/hurting bodies tied to those imported positions, with per-sprite hitboxes and behavior gates for the atlas-backed Rex, Clappin' Chuck, Banzai Bill, sliding Koopa, red shell, and jumping Piranha visuals. Runtime sprite tiles are now decoded from imported SNES 4bpp sprite VRAM and colored through eight per-level OAM palette row textures selected from each tile's property byte; the old single preview-row atlas remains only as fallback. Flying question block wings, the unused flying block face, Clappin' Chuck, and jumping Piranha use the current Lunar Magic Universal OAM preview recipes where available, and block-style sprite actors now feed a small solid-body resolver so Mario can stand on the imported flying question block. Sprite `0x8E` is a warp-hole/control marker and is no longer spawned as a visible runtime actor, though debug sprite markers can still expose it. Sprite `0xC7` currently has no native visual recipe in the runtime, so its translucent placeholder is debug-overlay-only rather than fake gameplay art. Rex now has its first native-inspired two-hit branch: a normal jump stomp changes it into a shorter, faster squished state instead of removing it immediately, and jumping Piranha has a first timed hidden/rise/extended/fall cycle that disables its hurtbox while hidden. The debug state reports the most recent actor interaction as `actor_event` and exposes the nearest actor ID/state; `actors_near` also reports each actor's visual-node count and current node visibility, which helps separate Mario OAM artifacts from nearby temporary sprite visuals. These actors now use the same imported floor-slope surfaces as Mario for temporary ground snapping where applicable, but exact sprite simulation still requires porting each sprite's native state machine, hitbox table, animation, palette, despawn/loading logic, and interaction branches.

Runtime goal note: sprite `0x7B` is the native goal tape (`Spr07B_GoalTape` in the C++ reference). Yoshi Island 1 imports one such sprite at screen `12`, x `4832`, and `GameScene` now creates a visible tape trigger from that record. Touching it enters a temporary course-clear state and plays the internal credits-preview sequencer; native bonus stars, walkout, score tally, overworld progression, and post-goal power-up logic remain pending.

Runtime death/restart note: falling below the imported level bounds by 96 pixels logs `smw-runtime: player_death`, increments the runtime death counter, reloads the current level geometry, and resets Mario to the current level's main entrance. This is a first playable-slice recovery path; native death animation, lives, midway entrance rules, overworld loss handling, and power-up/coin persistence semantics remain pending.

Runtime capture note: `tools/capture-wayland.sh` launches the Godot .NET binary with `--display-driver wayland`, waits for the exact launched PID to appear in Sway, moves it to workspace `6` by default, floats/resizes it to the intended 3x SNES viewport, waits for the `smw-runtime` level log, and captures that compositor rectangle with `grim`. This avoids the previous false-positive capture of existing terminal windows whose titles contained `smw`.

Runtime RCON capture note: the loopback debug server supports `snapshot`/`capture_now` for immediate viewport PNG writes and `capture <path> <frames>` for scheduled writes after process frames. RCON command parsing deliberately keeps `:` inside path tokens so `res://generated/...` paths remain valid.

Runtime capture limitation note: Godot's headless dummy renderer does not expose a readable viewport texture for PNG capture. `--smw-capture` and RCON capture commands now report `headless_viewport_texture_unavailable` cleanly in that mode; use `tools/capture-wayland.sh` for visual captures because it starts a bounded Wayland/OpenGL run on the configured workspace and grabs the compositor output.

Runtime RCON control note: long Wayland playtest sessions can now enable or disable debug presentation and interference live. `restart`/`reset`/`reload` rebuilds the current level and returns Mario to the imported entrance; `spawn x y [powerup]` places Mario at a coordinate and can apply `small|big|cape|fire` first so the final coordinate is not shifted by form-change foot preservation; `overlays`/`gizmos` rebuilds the world presentation and player HUD with collision, slope, actor, pipe, goal, screen, semantic markers, and Mario collision sensor dots; `actors` freezes runtime sprite actor motion and interaction without hiding them; `actor_visuals`/`sprite_visuals` hides or restores runtime sprite actor nodes while leaving their simulation state intact, which helps isolate Mario OAM glitches from nearby enemy or block sprites; `god` suppresses actor damage while still recording the attempted interaction in `actor_event`; `ground on|off` forces the grounded flag for controlled probes; `sensors [tag]` dumps Mario's current head, side, and three foot probes with Map16 tile/source and diagonal-pipe cell role; `trace <frames> [inputs...] [tag=name]` queues deterministic input and logs per-frame native-unit state, camera, foot-tile, and nearest-actor data for unattended debugging. `trace_oam <frames> [inputs...] [tag=name]` adds per-frame `player_oam` metadata to that trace so animation or stray-pixel bugs can be correlated with the exact native pose, descriptor, tile, and atlas region selected that frame.

Runtime RCON audio note: `audio status` reports whether the internal APU probe is enabled, whether the `SmwAudio` node exists, the current level music bank, loaded probe samples, active voice count, current preview frame, loop length, `AudioStreamGenerator` frames available, and cumulative mixer frame/call/time counters. `audio off` stops the current preview, clears voices, and disables processing on the audio node; `audio on` re-enables processing and restarts the current level preview. `audio sample <id>`, `audio jump`, `audio spin`, `audio music <bank>`, and `audio stop` exercise the same internal sample, SFX, and music-preview paths from a live RCON session. This is a diagnostic/performance isolation control for long Wayland sessions, not the final SPC/DSP sequencer.

Runtime RCON performance note: `perf`/`fps`/`stats` reports current FPS, Godot process/physics frame milliseconds, render draw-call/object counts, physics tick rate, pause/queued-frame state, total scene node count, actor/tile/collision counts, player OAM sprite count, and the same audio generator status line used by `audio status`. Use it before and after `audio off`, `actors off`, or `overlays off` when a visible Wayland run appears slow.

Runtime RCON physics note: `state`, `trace`, HUD/debug labels, and the new `physics`/`phys` command expose transient movement fields needed for exact SMW tuning: subpixels, P-meter, facing, rendered player pose/facing, spin-jump state, running-takeoff carry, jump-hold frames, cape-float timer, current slope kind/player/type metadata, and the current native jump-table lookup. `pmeter <value>` sets the live P-meter for deterministic sprint/jump probes. `collision [x y radius]` also reports nearby slope line `kind`/`snap` values, which identifies whether a visual slope came from a normal native slope table row or a diagonal-pipe fallback segment whose native snap distance is zero. The current `slope_player` value is now used by horizontal physics on the following frame, so RCON traces can show the native slope row that selected acceleration, cap, drag, and no-input slide behavior.

Runtime player OAM debug note: `player_oam`/`oam`/`pose` dumps the current Mario pose bridge over RCON or the debug command file. The log reports the native pose, table pose after power-up offset, palette variant, descriptor and displacement bases, head/body upload pointer bytes, and each of the first four OAM slots with descriptor byte, resolved dynamic GFX32 tile, displacement, 8x8/16x16 size, visible flag, local position, and atlas region. `tools/smw-rcon.sh` now drains multi-chunk socket responses so these long OAM diagnostics are not truncated. This exists specifically to diagnose stray pixel fragments and wrong animation frames while the remaining static descriptor and cape/Yoshi OAM mappings are still pending.

Sprite GFX note: the importer now writes `spritesets/level_*_spritegfx*_8x8.png`, raw `*_vram.bin`, and matching metadata from the same sprite upload table used by the native code. The PNG files are raw sprite VRAM previews; runtime actors prefer the raw VRAM plus per-level CGRAM palette so OAM palette bits can be honored. Correct Koopa, Yoshi, power-up, and effect rendering still requires porting each sprite's OAM assembly, tile index, tile size, flip, priority, and state-machine animation rules.

External Godot physics reference note: Tortellini at `https://github.com/ToadsworthLP/Tortellini` was checked as a Godot/C# Mario-style controller reference. The useful pieces are architectural rather than numeric: explicit movement states, slope slide/floor-normal handling, and snapping around `MoveAndSlide`. Its Godot 3-era 3D implementation and exported feel constants are not used as the source of truth for this 2D classic-platformer-compatible runtime; the native SMW tables remain the target.

The key vanilla transition invariant is:

```text
destination = current_overworld_map_high_bit | screen_exit_low_byte
secondary = raw_r11 >> 1
```

The importer also preserves the raw `R11` byte and the old property-bit destination projection so Lunar Magic and vanilla differences are not lost. Lunar Magic exits can still use property bits differently, but the verified vanilla path follows the native `LoadLevel` behavior fixed in the C++ reference.

For Yoshi Island 1, the direct pipe route imported from the ROM is:

```text
level 105, screen 07 -> level 1CB, secondary=0, raw_r11=00, exit_low=CB
```

`tools/import-smw.sh` imports direct screen-exit targets by default so level `1CB` is available to Godot even though it is reached through a transition.
