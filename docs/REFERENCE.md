Importer references translated into `tools/smw_import.py`:

- LoROM address conversion and decompression from `assets/util.py`
- Level object length parsing, Map16, palette, graphics, level pointer, and sprite pointer addresses from `assets/compile_resources.py`
- Foreground/background GFX upload order from `kUploadGraphicsFiles_FGAndBGGFXList` in `src/smw_00.cpp`; level `105` uses tileset `7`, which uploads GFX `15`, `1B`, `17`, and `14` into level VRAM order.
- Sprite GFX upload order from `kUploadGraphicsFiles_SpriteGFXList` and `UploadGraphicsFiles` in `src/smw_00.cpp`; level `105` and its direct pipe target `1CB` use sprite GFX setting `8`, which uploads GFX `20`, `13`, `01`, and `00` into the `$6000-$7FFF` sprite VRAM window.
- Screen-exit property semantics from `src/smw_0d.cpp` and level-load destination construction from `src/smw_05.cpp`
- Lunar Magic Universal's current screen-jump object behavior: extended object `01` updates the object stream screen cursor after the marker object is parsed, which keeps later level geometry on the intended screens.
- Lunar Magic Universal's current vanilla extended-object projection for common one-off objects: moons, invisible 1-ups, question/switch blocks, midway bars, Yoshi coins, goal markers, boss doors, and generic one-tile extended objects are now emitted into partial Map16 layout data. The verified `105` and `1CB` imports currently report no unsupported extended objects.
- Player graphics source data from `GFX32`/`GFX33`, player palettes, and `PlayerGFXRt` tile pointer/OAM placement tables.
- SPC upload bank addresses from `assets/compile_resources.py`: engine `0x0E8000`, samples `0x0F8000`, level music `0x0EAED6`, overworld music `0x0E98B1`, and credits music `0x03E400`.
- Vanilla secondary entrance tables from `0x05F800`, `0x05FA00`, `0x05FC00`, and `0x05FE00`, including the Yoshi Island 1 return-pipe entry at `0x1CB`.
- BRR preview decoding follows the native `assets/util.py` BRR decoder and the SPC upload block format used by `src/smw_spc_player.cpp`. The vanilla DSP sample directory starts at SPC RAM `$8000`.

Palette note: raw 8x8 GFX tiles are not enough to show final colors. The level layout preview renders through Map16 tile words because those words carry CGRAM row bits 10-12, priority, and flip flags. The importer now writes `palettes/level_*_palette.json` as a full 256-color level CGRAM image. For the verified vanilla ROM, this is assembled from the level header's back-area color, BG palette, FG palette, sprite palette, layer 3, object, berry, player, and animated-color tables. `SmwAssetTool verify-palettes` now independently rebuilds the same global palette tables and level `105`/`1CB` CGRAM words/RGB values directly from the ROM, so palette drift is caught outside the Python importer. The importer also recognizes the Lunar Magic custom palette hijack at `$00A5C0 -> $0EF570` and the `$0EF600` per-level palette pointer table structurally, but the validation gate still uses the clean SMW USA ROM unless ROM support is explicitly widened later.

GFX note: foreground/background and sprite VRAM atlases are resolved per level. Clean vanilla levels use the native upload tables, while Lunar Magic Super GFX bypass data is recognized through the table pointer at `$0FF7FF` and slot words for `FG3/BG1/FG2/FG1` and `SP4/SP3/SP2/SP1`. Vanilla SMW GFX slots are stored as 3bpp for most normal files, so generated previews expand them into 4bpp and populate 128 tiles per uploaded GFX file, yielding the full 512-tile BG and sprite VRAM windows needed by Map16/tilemap words. The importer can also resolve ExGFX pointer tables structurally, but generated validation assets are still produced from the verified vanilla ROM.

Map16 note: foreground Map16 IDs are not a flat `map16_id * 4` index into `$0D8000`. The importer now ports the native `InitializeMap16Pointers()` table from `src/smw_05.cpp`, including the global-vs-tileset bitmask, tileset base pointers, and the grassland/YI1 override slots for tilesets `0` and `7`. Level `105` therefore resolves tile `0x100` through the YI1 grassland Map16 pointer path before rendering the Godot atlas and runtime tile sprites. Standard object `0x13` ground-edge expansion also mirrors Lunar Magic Universal's explicit full-Map16 ID tables; type `7/8` middle-row ledge cells are emitted as `0x040/0x041`, not guessed as high-page `0x140/0x141` tiles.

Audio note: the importer preserves the original SPC engine/sample/music banks. Godot runtime playback now uses a C# internal APU probe that parses the SPC upload streams, reads the vanilla instrument table from the engine RAM image, decodes selected BRR entries from the sample directory, and streams them through `AudioStreamGenerator`; the WAV files are only importer verification artifacts. The command probes cover the native SPC port-1 jump and two-note command shapes, and the menu exposes decoded BRR sample probe buttons for samples `07`, `08`, `09`, `0E`, and `10`, matching the runtime SFX fallback sample set. Named gameplay SFX probes now cover the current playable events: coins, dragon coins, one-ups, Rex/stomp reward sounds using the native `0x13..0x19` stomp command range, spin-jump block breaks, flying-block power-up rewards, Fire Mario's native port-3 command `0x06` fireball shot, hurt/death, and course clear. Before using fallback probe notes, these events now read the SPC RAM SFX pointer tables at `$5681` for channel-1 style commands and `$5619` for channel-3 style commands, then decode the simple note-length, volume, instrument, note, and pitch-envelope command stream into scheduled `AudioStreamGenerator` voices. Each probe records the intended native sound port/command, whether a native stream was used, the SPC pointer, and decoded note count in `smw-audio: sfx=...` logs and RCON audio status. The menu music buttons drive a small C# pattern sequencer through imported BRR instruments for level/overworld/credits previews. Gameplay level entry now reads the imported level-header `music_index` and starts the corresponding internal preview automatically, including after pipe transitions. The current mixer prunes inactive voices, caps active voices and per-frame generator fill work, and can be disabled with `--smw-no-audio` or `SMW_AUDIO=0` for performance isolation. Exact SMW music and SFX still require porting the complete SPC command sequencing, ADSR, pitch sweep, echo, and DSP state.

Runtime collision note: `GameScene` now renders the generated Yoshi Island 1 Map16 placements through a single palette-aware custom draw layer and derives temporary merged AABB collision rectangles from the imported placement source labels. Imported diagonal ledge, diagonal pipe, and slope edge cells emit per-Map16-tile slope segments rather than long connected-component averages, so adjacent slope objects do not create large false walkable lines. Slope-family support/fill/assist cells are deliberately not emitted as temporary rectangular solids because those AABBs create hidden stair steps inside visual terrain slopes. Right diagonal pipe cells are the exception: floor-slope, interior-body, and underside Map16 IDs are tracked separately, so the outer traversal/ceiling slope lines remain available while interior body cells can still reject embedded player positions without reusing floor cells as horizontal body blockers. Standard slope collision now reads the Map16 ID family for the actual edge tile and emits gradual `4 px`, normal `8 px`, or steep `16 px` surface segments instead of treating every slope cell as a full 45-degree ramp. Native zero-distance slope snap entries are preserved as zero instead of being widened to the fallback tolerance, which keeps non-floor pipe/slope pieces from creating broad hidden support; the diagonal-pipe traversal tiles `0x01C5` and `0x01C7` still use the temporary broad support because the exact Map16 act-as routine is not yet ported. Right diagonal pipe underside tiles can emit temporary ceiling slope segments, shown in cyan debug overlays, so the pipe body can block upward movement while slope interiors remain passable. Player floor-slope contact currently probes center plus both feet and checks the leading foot first when moving, which makes diagonal pipe lips less fragile at tile boundaries while the native Map16 act-as slope code remains unported. The importer follows Lunar Magic Universal's current `0x12` standard slope projection, including native slope overwrite tile adjustment, and the newer left diagonal ledge lower-row placement, bottom-row plain fill, first-fill-row notch, and slope/line overwrite flags. This is useful for playable traversal, but it is not a substitute for the final Map16 act-as table, slope semantics, and block interaction routines.

Runtime diagonal-pipe underside note: the temporary right-diagonal pipe underside solver now skips active horizontal walking when Mario is not moving upward. This keeps a headless reproduction at `x=2056,y=304` in level `105` while walking left under the sloped pipe instead of letting underside correction shove Mario into a pipe transition path. Diagonal-pipe body and ceiling recovery also yields when Mario is already supported by the imported floor-slope cells, which prevents the previous one-frame shove from `x=2025` to `x=2048` inside the sloped pipe cluster. Stationary embedded-pipe recovery still resolves the older `x=880,y=304` probe to the known `x=896` boundary. The pipe body's coarse horizontal blocker can still push Mario out of the green pipe volume; replacing that with exact native Map16 act-as sampling is still pending.

Runtime block interaction note: `std_generic_08`/Map16 `0x11E` turn-block cells are now a focused runtime interaction for the Yoshi Island 1 slice. A non-small spin jump landing on these imported cells hides the tile in the batched Map16 layer, removes the tile from the runtime tile lookup, rebuilds collision data, and logs `smw-runtime: block_break`. Imported static question blocks now preserve their extended-object content in the generated source label (`flower`, `feather`, `star`, `coin`, multi-coin, or Yoshi/1-up style), are emitted as solid runtime block tiles, and react to old-school head probes after an upward solid collision. Those underside hits swap the Map16 cell to the used block face, rebuild collision data, bump Mario downward, and spawn a runtime item actor for flower/mushroom, feather, star, or 1-up rewards without immediately changing Mario's state. Imported block-style sprite actors `0x83` and `0xB9` are also treated as temporary solid actor bodies; the flying question block `0x83` gets a deterministic wing bob and resolves top, side, and underside player contacts. Underside hits on `0x83` mark the block used, swap to the used Map16 face, resolve the Lunar Magic Universal content rule `X&3`, and spawn a runtime item actor for the mushroom, flower, feather, or 1-up reward. These spawned items use the native `0x74/0x75/0x76/0x77/0x78` sprite IDs and the LMU `PowerUpAndItemDraw` OAM tile/properties, then apply the power-up, score, or life when Mario collects them. This is intentionally narrower than the native block system; exact turn-block bounce sprites, debris, timers, full item state machines, multi-coin timers, Yoshi/item-box branches, and the full Map16 act-as dispatch remain pending.

Runtime sprite graphics note: enemy and command-sprite visuals are an incremental OAM preview bridge over the generated per-level sprite VRAM atlas. The Yoshi Island 1 set covers Banzai Bill, Rex, Clappin' Chuck, sliding Koopa, shell colors, jumping Piranha, flying question-block wings, and now several additional Lunar Magic Universal recipes: Pipe Lakitu, moving ledge hole, goal tape, Lakitu cloud, scale platform, green gas bubble, and Volcano Lotus. These recipes are visual assemblies only; most sprite AI, native animation phases, sprite-to-sprite interaction, and exact OAM priority are still pending.

Runtime player graphics note: `GameScene` now draws Mario from the generated GFX32 player atlas through the native `PlayerGFXRt` data path for the first big-Mario pose set. The importer preserves `player_xy_disp_index_index` from `$00DCEC`, `player_xy_disp_index` from `$00DD32`, signed X/Y displacement words from `$00DD4E/$00DE32`, `powerup_tileset_index` from `$00DF16`, `tiles_index` from `$00DF4C`, OAM tile descriptors from `$00DFDA`, head/body tile pointer indices from `$00E00C/$00E0CC`, tile X-flip flags from `$00E18C`, `kSetPlayerPose_WalkingPoseCount` from `$00DC78`, and `kSetPlayerPose_AnimationSpeedTable` from `$00DC7C`. The runtime maps OAM descriptors `0/1/2/3` through the dynamic upload pointer math used by `PlayerGFXRt_00F636`, so head/body source tiles come from GFX32 offsets instead of treating descriptor bytes as raw source tile IDs. Other direct/static descriptor tile numbers are temporarily suppressed because they refer to native dynamic VRAM/OAM char numbers rather than raw GFX32 atlas indices; rendering them directly produces stray pixel fragments until the exact VRAM upload mapping is ported. Dynamic regions are also bounds-checked against the generated player atlas so a bad or still-unported descriptor hides the slot instead of sampling unrelated pixels. Mario's visual node is snapped to the integer player position while the physics state keeps subpixels, matching SNES OAM placement more closely and avoiding subpixel texture shimmer. The generated PNG atlases use a full OBJ palette row 8 layout: fixed colors `0-1`, vanilla object colors `2-5`, and player dynamic colors `6-F` from `$00B2C8`; the importer writes Mario, Luigi, Fire Mario, and Fire Luigi variants, and the runtime currently selects variant `2` for the fire power-up. The current runtime player state tracks SMW power-up forms `0..3`; `_state.Y` is treated as the native/visual anchor, while the temporary collision rectangle starts 16 px below that anchor and uses 16px small/ducking or 32px big-family height, preserving foot position across form changes and duck toggles. Fire form now has a first attack bridge: a run/Y pressed edge enters native shoot pose `67` for 10 frames and spawns a capped player fireball using the `SpawnPlayerFireball` offsets/speeds; exact fireball smoke, extended-sprite slots, and fire-kill normal-sprite transformations remain pending. Mario's rendered OAM bridge keeps the native `-1px` screen-space bias for small and ducking forms, while big/cape/fire forms add the 16px form-height delta so the 32px visual body shares the same collision-foot anchor instead of floating above it. The current animation bridge uses deterministic frame timers for idle/walk/run, switches high-speed running into the native `+4` pose range, maps opposite-input ground turns to pose `13`, switches grounded ducking to native pose `60`, and cycles spin-jump pose/facing through the native `DATA_00CE99/00CEA1` tables; static descriptor VRAM mapping, cape/Yoshi variants, cape OAM, priority, hide-mask behavior, and native hitbox tables still need the direct SMW pose/OAM port.

Asset-pipeline note: Python is currently used only for the offline development extractor because it is fast to iterate and easy to compare against ROM bytes. The Godot runtime consumes generated assets and does not call Python. The intended end state is a C# importer/editor tool or C# asset-pipeline project so asset extraction can live inside the Godot/.NET codebase.

Pipe target layout note: vanilla Yoshi Island 1 resolves the screen `07` pipe to level `1CB`, not `0CB`. Level `1CB` uses underground tileset `3`; the partial object expander now covers its standard horizontal pipes plus underground ceiling ledges and ceiling edges, so `level_1CB_partial_tilemap.json` contains the target room's main shell geometry. Pipe objects now use Lunar Magic Universal's foreground-preservation rule, so overlapping terrain stays in front of shaft/body cells in both generated previews and runtime tile selection.

Runtime level asset note: `GameScene` loads the current level through `generated/smw/manifest.json` and uses the manifest's per-level `tileset_assets` and `layout_preview` paths. Level `105` is still the startup level, but the renderer no longer assumes `level_105_tileset7_*` filenames internally.

Runtime transition scaffolding note: `GameScene` can rebuild world geometry, collision rectangles, HUD previews, and player spawn from another imported level. The CLI argument `--smw-test-level=1CB` is used by `tools/check-headless.sh` to verify that the imported direct pipe target loads with generated collision rectangles.

Runtime entrance note: `GameScene` resolves entry placement through the imported vanilla tables rather than scanning for the first plausible floor tile. Main entrances read `$05F000` for the Y index, `$05F200` for X/action, and `$05F600` for the screen. Secondary screen exits use the screen-exit destination as the secondary entrance ID and then read `$05F800/$05FA00/$05FC00/$05FE00` for target level, Y, X/screen, and entrance action; the high three bits of `$05FC00` are the native X-position index, while the low five bits are the target screen. The C# native extractor now independently verifies `levels/secondary_tables.json` byte-for-byte from those ROM tables, including the anchors used by level `105`, direct pipe target `1CB`, and secondary entrance `1CB -> 105`. The runtime now applies a bridge for those entrance actions: settings `1..4` briefly lock input and move Mario left, right, up, or down with the native pipe-action direction, while setting `6` performs the vanilla shoot-out vector from `PlayerState07_ShootOutOfPipe` with the initial one-frame move, hold, deferred launch, and post-release velocity. The verified YI1 path now loads `105 -> 1CB` at the `1CB` main entrance and `1CB -> 105` through secondary entrance `1CB` at screen 8 (`spawn=2072,242` before the action-6 movement).

Runtime viewport note: the game scene now uses a `256x224` logical viewport, matching the SNES visible level area, while `Main` requests a `768x672` Wayland window for normal visible runs. The camera follows horizontally and vertically, clamped to generated tile bounds, so lower terrain in Yoshi Island 1 remains inspectable during drops. Debug asset previews no longer determine the playable viewport scale.

Runtime debug launch note: `--smw-test-spawn=x,y` places Mario at an explicit world coordinate after the level is loaded, and `--smw-test-powerup=small|big|cape|fire` forces the runtime form for hitbox checks. When both are present, the power-up is applied before the spawn coordinate so the requested debug coordinate is not shifted by the form-change foot-preservation logic. These are intended for reproducible viewport captures and lower-route inspection.

Runtime input script note: `--smw-input-script=/path/to/script` autostarts the game and feeds deterministic per-frame C# `FrameInput` values. The current bridge is intentionally simple: one segment per line, blank lines and `#` comments ignored, first token as frame count, and remaining tokens as held inputs (`left`, `right`, `down`, `jump`/`B`, `spin`/`A`, `run`/`X`/`Y`) separated by spaces, commas, colons, semicolons, or `+` signs. Native `smw/` converter directives beginning with `@` are ignored for now, and menu/shoulder tokens `Start`, `Select`, `Up`, `L`, and `R` are accepted as no-ops so generated `.input` files can be reused for in-level probes. `jump` and `spin` set the pressed-edge flag only on the first frame of their segment.

Native recording note: `/path/to/native-reference` can now produce and consume frame-counted `.input` scripts from cold boot with `--record-input` and `--input-script`, and that is the preferred sync path. Native trace output includes player subposition/subspeed plus nearest-sprite subposition/speed fields, so Godot divergence reports can distinguish integer rounding from actual motion drift. `tools/run-native-input-recording-wayland.sh` records native input visibly through Wayland with an isolated generated `XDG_DATA_HOME`, writes `latest-native-full.input`, selects a level-start marker from `K`/`manual_k` or `auto_level_start`, and slices `latest-level-start.input` for Godot. `tools/run-native-input-wayland.sh` replays the full route in native without save states. `tools/run-recording-compare-wayland.sh --input full-route.input --level-start-frame N` opens native cold-boot playback next to Godot running the sliced level-start input, and `tools/run-recording-trace-compare.sh` converts native `state_trace_schema=2` records plus Godot `smw-debug-trace` lines into JSONL traces and reports the first position/power-up divergence after applying the current `-64 px` native-to-Godot Y offset. `tools/slice-input-script.py` is the explicit two-signal bridge: signal one is the full game-start recording, signal two is the level-start frame used to make Godot's level slice. The compare wrappers default to a two-frame neutral Godot input prepad because subpixel trace analysis showed that this phase aligns the level-start movement sequence without retuning physics constants. The old `tools/run-native-replay-wayland.sh` save-slot replay path is intentionally disabled because replaying native slot snapshots can mutate the live `smw/` save-state directory.

Headless trace note: `tools/run-recording-trace-compare.sh --headless` runs the native binary directly with SDL dummy video/audio and runs Godot with `--headless --audio-driver Dummy`, avoiding any Sway/Wayland window while preserving the same native-vs-Godot trace comparator. The native side intentionally reuses `generated/smw/native-xdg` and deletes only `save0.sav`; its `smw.srm` is kept because the recorded cold-boot route depends on that SRAM state to reach the same Yoshi Island 1 level-start path. Absolute or repo-relative trace/output paths are normalized before launch, and Godot is executed from the project directory because the .NET binary can fail to instantiate C# scripts when launched with an absolute `--path`.

TAS diagnostic note: `tools/convert-tas-input.py` is a local copy of the native-source TAS conversion path adapted for Godot input scripts. It accepts Snes9x `.smv`, BizHawk `.bk2`, lsnes `.lsmv`, or a TASVideos zip that contains one of those files, then emits frame-counted inputs compatible with `DebugLoadInputScript`. `tools/prepare-tas-diagnostic.sh` downloads and caches TASVideos `3849S` under ignored `generated/smw/tas/`, converts the full movie, and writes a diagnostic slice using the current native-source trace point where active gameplay is present around source frame `1525`. That movie enters Yoshi's Island 2 first, so the harness is not a Yoshi's Island 1 sync claim. The Godot runtime now defaults level starts to small Mario to match clean SMW new-game state; TAS wrappers also pass `--smw-test-powerup=small` explicitly. This remains a desync inspection tool while physics, slopes, enemies, camera, and transitions are incomplete.

Runtime RCON controller note: live debug control supports one-shot `input <frames> ...`, single-frame `tap ...`, persistent `hold ...`, and `release`/`neutral`. Persistent holds generate `JumpPressed`/`SpinPressed` only on the first frame where the held button changes from up to down, so `hold right run jump` behaves like a controller button press and then a held jump rather than repeatedly retriggering jump every physics tick.

Runtime debug overlay note: `--smw-debug-overlays` adds world-space diagnostics for the current partial port: player hitbox/feet/form label, active `256x224` camera rectangle, merged collision rectangles, slope lines, pipe trigger rectangles, goal tape trigger rectangles, runtime sprite actor hitboxes, imported sprite/object markers, screen boundaries, and coin/block markers inferred from generated Map16 tile sources. The debug HUD also reports the Map16 coordinate, tile ID, collision role, and source label under Mario's feet. These gizmos are debugging aids for comparing importer placement and collision behavior; they are not game objects and should stay disabled for normal playtests.

Runtime collision probe note: RCON `collision [x y radius]` reports the nearest temporary solid rectangles and slope segments around a world point, including solid step-up/vertical flags and slope ceiling flags. With no explicit point it probes around Mario's current hitbox center. This is intended for stuck-player and misplaced-pipe reports where the overlay is visible but the exact blocker is not obvious from a screenshot.

Runtime diagonal pipe probe note: RCON `pipe [x y radius]` reports nearby generated right-diagonal pipe floor/body/ceiling cell coordinates. It uses the same tracked cell sets that feed temporary pipe collision recovery, so a stuck report can distinguish missing floor-slope support from a body or ceiling cell being interpreted too broadly.

Runtime pipe note: pipe debug rectangles are rebuilt from imported screen-exit records and the corresponding generated vertical pipe top, horizontal pipe end, or right-diagonal pipe cluster Map16 placements. For level `105`, this puts active triggers on the screen `07` pipe geometry, including the sloped pipe cluster, instead of the old hardcoded screen `01` marker; for level `1CB`, the horizontal pipe end now has a left/right-triggered rectangle for the return screen exit.

Runtime sprite note: `GameScene` loads generated `sprite_layer.sprites` records and renders their spawn points as debug markers with sprite IDs. The current coordinate decode uses the vanilla screen nibble plus 8-bit x byte and low y nibble, which is enough to inspect Yoshi Island 1's 34 imported sprite records. The first runtime actor layer turns common YI1 enemy records into simple moving/stompable/hurting bodies tied to those imported positions, with per-sprite hitboxes and behavior gates for the atlas-backed Rex, Clappin' Chuck, Banzai Bill, sliding Koopa, red shell, and jumping Piranha visuals. Runtime sprite tiles are now decoded from imported SNES 4bpp sprite VRAM and colored through eight per-level OAM palette row textures selected from each tile's property byte; the old single preview-row atlas remains only as fallback. Flying question block wings, the unused flying block face, Clappin' Chuck, and jumping Piranha use the current Lunar Magic Universal OAM preview recipes where available, and block-style sprite actors now feed a small solid-body resolver so Mario can stand on the imported flying question block. Sprite `0x8E` is a warp-hole/control marker and is no longer spawned as a visible runtime actor, though debug sprite markers can still expose it. Sprite `0xC7` still has no native visible gameplay art, so its translucent placeholder remains debug-overlay-only; touching its imported hitbox now follows the first `Spr0C7_InvisibleMushroom` slice by replacing the hidden marker with a real sprite `0x74` mushroom actor, offsetting it upward by 15 px, assigning a `-4 px/frame` pop speed from native `-0x40`, and blocking immediate re-collection for 32 frames. Rex now has its first native-inspired two-hit branch: a normal jump stomp changes it into a shorter, faster squished state instead of removing it immediately, and its temporary terrain resolver uses a separate 16x16 terrain footprint instead of the narrower player-contact clipping box so slope/ground snapping does not delete the first level-105 Rex. The left flying question block `0x83` now follows the native forced `spr_xspeed = -12` rule while active, stops after use, and resolves its `coin/mushroom-or-flower/feather/1-up` content from the spawn-time X nibble like native `spr_table151c`, not from the moved runtime X. Stomped actors now feed a first native `GivePoints`-style reward table: Rex's first normal stomp uses reward slot 1 for 200 displayed points, the consecutive-stomp counter is exposed as `stomp_chain`, and the eighth reward branch maps to the runtime one-up path. The debug state reports the most recent actor interaction as `actor_event` and exposes the nearest actor ID/state; trace lines now also include tracked `9F`, `AB`, `83`, and `BD` actor slots, while `actors_near` reports each actor's visual-node count, current node visibility, and terrain rectangle. These actors now use the same imported floor-slope surfaces as Mario for temporary ground snapping where applicable, but exact sprite simulation still requires porting each sprite's native state machine, hitbox table, animation, palette, despawn/loading logic, interaction branches, score sprites, and sound effects.

Runtime jumping-Piranha note: sprite `0x4F` / `0x50` no longer uses the old temporary fixed visual cycle. Its runtime actor origin now uses the native-style `+8 px` spawn X offset and pipe/home Y origin, then follows a first `Spr04F`-shaped state machine: hidden wait, no-wake while Mario is inside the `[-27,+28)` horizontal window, `-4 px/frame` launch speed, `0.125 px/frame` rise acceleration until the `-1 px/frame` transition, then a slow falling phase capped at `0.5 px/frame` before landing back into a 64-frame hidden wait. The 1600-frame zero-tolerance headless guard remains green, and the first level-105 `0x4F` actor position now aligns in the 2000-frame diagnostic; the next mismatch there is Mario horizontal subpixel state on the ground-jump/ledge frame, not Piranha placement.

Runtime goal note: sprite `0x7B` is the native goal tape (`Spr07B_GoalTape` in the C++ reference). Yoshi Island 1 imports one such sprite at screen `12`, x `4832`, and `GameScene` now creates a moving tape visual from that record. Its test-slice motion follows the native `kSpr07B_GoalTape_YSpeed` cadence, alternating `+0x10` and `0xF0` every 124 frames, while the course-clear gate uses the generated Map16 goal-post bounds. Touching the gate enters a temporary course-clear state, locks normal player input, starts a rightward walkout, and plays the internal credits-preview sequencer; native bonus stars, tape score, walkout endpoint, score tally, overworld progression, and post-goal power-up logic remain pending.

Runtime death/restart note: falling below the imported level bounds by 96 pixels, letting the level timer reach zero, or taking harmful sprite contact while small logs `smw-runtime: player_death`, increments the runtime death counter, decrements the temporary life counter, reloads the current level geometry, and resets Mario to the current level's main entrance while lives remain. Harmful sprite contact while powered now follows a first `DamagePlayer_Hurt`-style branch: Mario powers down to small, receives a native-style `0x7F` post-hit invulnerability timer reported as `hurt` in HUD/RCON/debug state, and currently keeps Mario in place instead of applying the old temporary knockback. When the temporary life counter reaches zero, the runtime now logs `smw-runtime: game_over`, freezes normal gameplay, stops the music preview, shows a `GAME OVER` prompt, and reports `gameover=1` through HUD/RCON state. Pressing Start/Jump or sending RCON `continue` restarts the first-level slice with fresh lives and reset temporary score/coin counters. RCON `timer`, `time`, or `clock` can report the current clock, set seconds with `timer 123`, or set exact native frames with `timer frames 1`; RCON `lives <n>` is available for deterministic game-over probes. This is a first playable-slice recovery path; native death animation, powered-down pose sequence, midway entrance rules, overworld loss handling, save-file continue rules, and exact power-up/coin persistence semantics remain pending.

External Godot physics reference note: Tortellini at `https://github.com/ToadsworthLP/Tortellini` was checked as a Godot/C# Mario-style controller reference. The useful pieces are architectural rather than numeric: explicit movement states, slope slide/floor-normal handling, and snapping around `MoveAndSlide`. Its Godot 3-era 3D implementation and exported feel constants are not used as the source of truth for this 2D classic-platformer-compatible runtime; the native SMW tables remain the target.

The key vanilla transition invariant is:

```text
destination = current_overworld_map_high_bit | screen_exit_low_byte
secondary = raw_r11 >> 1
```

The importer also preserves the raw `R11` byte and the old property-bit destination projection so Lunar Magic and vanilla differences are not lost. Lunar Magic exits can still use property bits differently, but the verified vanilla path follows the native `LoadLevel` behavior fixed in the C++ reference.

For Yoshi Island 1, the direct pipe route imported from the ROM is:

```text
level 105, screen 07 -> level 1CB, secondary=0, raw_r11=00, exit_low=CB
```

Runtime pipe activation must be mapped through the same exit-enabled object rules Lunar Magic Universal uses for undefined-exit scanning, not by just picking a nearby pipe tile. A vertical pipe object (`0F`) is enterable only when its low size nibble is nonzero, a horizontal pipe object (`10`) is enterable only when its high size nibble is nonzero, and a right-diagonal pipe object (`39`) is exit-capable when it is on a screen with a screen exit. When multiple exit-enabled objects exist on one exit screen, the runtime follows LMU's `screen_exit_tile_rect` priority and registers exactly one trigger: `0F` type `1` first, other nonzero `0F` pipes next, `10` horizontal pipes next, and `39` right-diagonal pipes last. In level `105`, that means screen `07` maps to the under-block vertical pipe object at tile `120,22`; the earlier same-screen vertical pipe has size `20` and is not an entrance. In level `1CB`, screen `01` maps to the horizontal return pipe at tile `28,22`, which resolves through secondary entrance `1CB -> 105`.

`tools/import-smw.sh` imports direct screen-exit targets by default so level `1CB` is available to Godot even though it is reached through a transition.
